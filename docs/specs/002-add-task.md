# 002: タスクの追加（add）と保存の仕組み

Issue: #2

## 概要

`memotodo add <タイトル>` でタスクを追加し、1 タスク = 1 マークダウンファイルとして保存する。
以降の機能が使う保存の仕組み（保存先の決定・ファイル形式・ID の採番）もここで確定する。

## コマンド例

```console
$ memotodo add APIを調査する
追加しました: 1 APIを調査する

$ memotodo add 設計 レビュー を依頼する
追加しました: 2 設計 レビュー を依頼する
```

- 複数の引数は半角スペース 1 つで連結して 1 つのタイトルにする。
- 成功時は標準出力に `追加しました: <ID> <タイトル>` を出力し、終了コード 0。

## 保存先

次の順で最初に見つかったものを保存先ディレクトリとする。

1. 環境変数 `MEMOTODO_DIR`
2. `$XDG_DATA_HOME/memotodo`
3. `~/.local/share/memotodo`

- タスクは `<保存先>/tasks/<ID 4 桁ゼロ埋め>.md` に保存する（例: `tasks/0001.md`）。
- ディレクトリが存在しなければ作成する。
- ID が 9999 を超えた場合はゼロ埋めなしでそのまま桁が増える（例: `tasks/10000.md`）。

## ID の採番

- `tasks/` 内のファイル名（`<数字>.md`）から読み取った ID の最大値 + 1。タスクが 1 件もなければ 1。
- 名前がこの形式に合わないファイルは無視する。

## ファイル形式

```markdown
---
id: 1
title: APIを調査する
status: todo
created: 2026-09-28T10:00:00+09:00
---

## メモ
```

- 先頭の `---` で囲まれた部分は `キー: 値` の 1 行ずつの形式（YAML のサブセット）。値は引用符で囲まない。
- `created` はローカルタイムゾーンの RFC 3339 形式（秒まで）。
- `## メモ` 以下はメモの追記（Issue #6）で使う。追加時点では空。

## 異常系

| 状況 | 出力（標準エラー） | 終了コード |
| --- | --- | --- |
| タイトルが指定されていない | `エラー: タイトルを指定してください` | 1 |
| タイトルが空白のみ | `エラー: タイトルを指定してください` | 1 |
| タイトルに改行が含まれる | `エラー: タイトルに改行は使えません` | 1 |
| 保存先に書き込めない | `エラー: <原因>` | 1 |

- タイトルの前後の空白は取り除いて保存する。

## コマンド全体の振る舞い（今回あわせて作るもの）

| 状況 | 出力（標準エラー） | 終了コード |
| --- | --- | --- |
| サブコマンドなし | 使い方（`使い方: memotodo <コマンド> [引数]` とコマンド一覧） | 1 |
| 未知のサブコマンド | `エラー: 不明なコマンドです: <名前>` と使い方 | 1 |

## テスト方針

- ユニットテスト: 保存先の決定、ID の採番、ファイル形式の書き出し、タイトルの検証。
- E2E テスト: `testscript`（`github.com/rogpeppe/go-internal/testscript`）で実際にコマンドを実行し、出力・終了コード・保存ファイルを検証する。保存先は `MEMOTODO_DIR` で一時ディレクトリに向ける。
  - テスト専用の依存として `go-internal` を追加する。

## スコープ外

- 同時に複数のプロセスから追加した場合の ID 衝突への対策
- ファイルの読み込み（一覧・詳細表示の Issue で扱う）
- `--help` などのオプション
