# 要件定義

## コンセプト

memotodo は、タスクに作業メモをぶら下げて管理する CLI アプリ。
タスクが主役で、メモは必ずいずれかのタスクに属する時系列の作業ログとなる。

## 方針

- シンプルな実装から始め、実際に使いながら少しずつ機能を追加・改善する。
- 外部ライブラリへの依存は必要になるまで追加しない。

## データモデル

### タスク

| 属性 | 内容 |
| --- | --- |
| ID | 1 から始まる連番。削除されても再利用しない |
| タイトル | 1 行のテキスト |
| ステータス | `todo`（未着手）/ `doing`（進行中）/ `done`（完了） |
| 作成日時 | タスク追加時に自動で記録 |
| メモ | 0 件以上。タスクに属する |

### メモ

| 属性 | 内容 |
| --- | --- |
| 本文 | 1 行のテキスト |
| 日時 | 追記時に自動で記録 |

## 保存

- 保存先はユーザーごとに 1 か所（グローバル）。
  - 環境変数 `MEMOTODO_DIR` があればそのディレクトリ。
  - なければ `$XDG_DATA_HOME/memotodo`、`XDG_DATA_HOME` も未設定なら `~/.local/share/memotodo`。
- 1 タスク = 1 マークダウンファイル（`tasks/<ID 4 桁ゼロ埋め>.md`、例: `tasks/0003.md`）。
- 新しいタスクの ID は、既存の最大 ID + 1。
- ファイル形式（案。詳細は各機能の仕様メモで確定する）:

```markdown
---
id: 3
title: APIを調査する
status: doing
created: 2026-09-28T10:00:00+09:00
---

## メモ

- 2026-09-28 10:30 仕様書を読んだ
- 2026-09-28 11:15 認証方式を確認した
```

## コマンド（MVP）

| コマンド | 内容 |
| --- | --- |
| `memotodo add <タイトル>` | タスクを追加する（ステータスは `todo`） |
| `memotodo list` | すべてのタスクを ID 順に一覧表示する（完了を含む） |
| `memotodo show <ID>` | タスクの詳細とメモを表示する |
| `memotodo start <ID>` | ステータスを `doing` にする |
| `memotodo done <ID>` | ステータスを `done` にする |
| `memotodo reopen <ID>` | ステータスを `todo` に戻す |
| `memotodo note <ID> <本文>` | タスクにメモを追記する |

## MVP の実装順（Issue 候補）

各項目を 1 Issue = 1 PR として、上から順に実装する。

1. タスクの追加（`add`）と保存の仕組み
2. タスクの一覧表示（`list`）
3. タスクの詳細表示（`show`）
4. ステータスの変更（`start` / `done` / `reopen`）
5. メモの追記（`note`）

## MVP のスコープ外（将来の候補）

- タスクの削除、タイトルの編集
- メモの編集・削除、エディタでの長文メモ
- 検索、ステータスでの絞り込み
- 期限・優先度・タグ
- プロジェクトごとの保存先
